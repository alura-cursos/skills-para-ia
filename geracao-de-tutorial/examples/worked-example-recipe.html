Worked example: the actual Stage 3 DB-indexing run

Setup. The Stage 1 cache is live (p99 210 ms, p50 135 ms, 2.5% peak error). Stack: Postgres 16 behind PgBouncer, app in Go 1.23. Source config: stage1-cache-v3. Target: the cache-miss path — make a miss cheap so the rare stampede that slips through does little damage, and reclaim the p50 the single-flight lock cost.

Execution. Applied 2 indexes + 1 query rewrite via online migrations (CREATE INDEX CONCURRENTLY, no table locks). Re-ran the CI benchmark (500 req/s) after each change. ~35 minutes total including index build time.

Per-change metric movement with comparison to the Stage 1 baseline
Change p99 (ms) p50 (ms) Throughput (req/s) Notes
Stage 1 baseline (cache only) 210 135 4,200 Stage 1 output (input to this stage)
+ idx products(category_id, active) 192 108 4,500 biggest miss-path query
+ idx order_items(product_id) 183 88 4,650 fixed the N+1 on product detail
+ batch-load rewrite (final) 175 68 4,800 SHIPPED — Stage 4 input

Outcome. p99: 210 → 175 ms and p50: 135 → 68 ms — Stage 3 reclaimed the single-flight overhead from Stage 1 (p50 is now well below the original 120 ms baseline) by making the miss path ~2× faster. A cache miss now costs 68 ms instead of ~300 ms, so the rare stampede that slips through does far less damage. Throughput kept climbing to 4,800 req/s.

Cost. Zero new hardware — the 2 indexes add ≈ 220 MB of storage, built online in ~20 min. Effectively free for halving p50.

⚠ Bear trap encountered mid-run

Right after the batch-load rewrite, the search cache silently went cold: hit rate on search:* dropped to 0%, origin QPS jumped to 100% of search traffic, and search p99 climbed 4× — three canary signals of a silent cache bypass. Cause: the rewrite changed how the query string is normalized before hashing, so the same user query now produced a NEW qhash → every lookup computed a fresh key → every request missed → every request hit the (now-indexed but still loaded) origin. Every key was unique; hit rate 0 everywhere. Fix: pinned key derivation to a versioned cacheKey(normalize(q)) and bumped the namespace to :v4. Cost of debug: ~2 hours. Documented in the bear-trap appendix.
