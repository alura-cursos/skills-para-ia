Anti-pattern gallery — what NOT to do, and why

Each row shows a common pattern that LOOKS reasonable but fails for a specific reason. Use this as a checklist when reviewing your own draft.

1. Visual encoding doesn't match the stated math

BAD: bars labeled as probabilities, claiming P(A)=0.30 and P(B)=0.40, but the bar heights are 30 px and 80 px on a 100 px axis (encoding 0.30 and 0.80).

GOOD: bars satisfying probability conservation — 0.30 → 30 px, 0.40 → 40 px, remaining 0.30 distributed across other outcomes summing to exactly 100 px.

✗ BAD — heights don't match claimed probabilities

✓ GOOD — probability conservation

The fix. Always compute bar heights from the claimed values: height = value × axis_height. Verify by summing: ALL probability bars must sum to axis_height within 1 px. Bear trap B.7 in SKILL.md.

2. SMIL <animate attributeName="textContent">

BAD: using SMIL to animate a text element's textContent. Silently fails in all browsers because textContent is a DOM property, not an XML attribute that SMIL can animate.

<!-- ✗ INVALID — silently fails -->
<text x="100" y="50">
  <animate attributeName="textContent"
           values="0.50;0.75;1.00"
           dur="3s" repeatCount="indefinite"/>
  fallback text
</text>

GOOD: three stacked text elements at the same position, each fading in during its phase via CSS @keyframes opacity.

<!-- ✓ VALID — CSS-based fade -->
<style>
  @keyframes show-A { 0%,30% {opacity:1} 35%,100% {opacity:0} }
  @keyframes show-B { 0%,30% {opacity:0} 35%,65% {opacity:1} 70%,100% {opacity:0} }
  @keyframes show-C { 0%,65% {opacity:0} 70%,95% {opacity:1} }
  .phase-A { animation: show-A 3s linear infinite; }
  .phase-B { animation: show-B 3s linear infinite; opacity: 0; }
  .phase-C { animation: show-C 3s linear infinite; opacity: 0; }
</style>
<text class="phase-A" x="100" y="50">0.50</text>
<text class="phase-B" x="100" y="50">0.75</text>
<text class="phase-C" x="100" y="50">1.00</text>

The fix. Never use attributeName="textContent". Always use stacked text + CSS opacity fade. Bear trap B.2 in SKILL.md. validate.py check 9 catches this.

3. :root selector inside SVG <style>

BAD: defining CSS variables in a :root { ... } block inside an SVG's <style> tag. The :root selector matches the page's <html> element regardless of context, so SVG-scoped variables LEAK to the entire document.

<svg id="anim-foo">
  <style>
    :root {                        <!-- ✗ LEAKS to entire page -->
      --bg: #0f1117;
      --text: #e6e8ee;
    }
  </style>
  ...
</svg>

GOOD: scope variables to a unique #id selector (the SVG's id or an inner <g> with id).

<svg id="anim-foo">
  <style>
    #anim-foo {                    <!-- ✓ scoped to this SVG only -->
      --bg: #0f1117;
      --text: #e6e8ee;
    }
  </style>
  ...
</svg>

The fix. Bear trap B.1. validate.py check 8 catches this.

4. Same color reused for two distinct concepts in one figure

BAD: using yellow #fbbf24 for both the spread band AND the mid-value dots in the same measurements figure. The yellow background of the band makes the yellow dots invisible.

GOOD: distinct hues for distinct semantic roles. Spread band stays muted blue; value dots remain yellow.

The fix. Bear trap B.9. No automated check; humans must spot this during the per-element review (Phase 7).

5. Dark-mode colors used on light mode without overrides

BAD: using --term-yellow: #fbbf24 (yellow) for prose spans on white background. WCAG contrast is ~1.6:1 — fails AA (4.5:1 required).

GOOD: light-mode override switching --term-yellow to #a16207 (darker yellow) with ~7:1 contrast on white.

The fix. Bear trap B.10. Use the canonical light-mode hex from reference/color-palette.md. No automated check; verify manually with a contrast calculator.

6. Formula presented without a worked example

BAD: "The weighted average is computed as mean = sum(w_i × x_i) / sum(w_i). This combines the values according to their weights." Then immediately moves to the next concept.

GOOD: the formula PLUS a worked-example callout with specific arrays, multiplication step-by-step, and a verified numerical result.

The fix. Pedagogical-review.js dimension 2 catches this. Every display formula must have a .callout.worked-example nearby.

7. Glossary term defined but never linked from prose

BAD: appendix defines <dt id="g-irrelevance">Irrelevance</dt> but no <a class="gloss" href="#g-irrelevance"> appears anywhere in the document. Reader who clicks "back" from the glossary lands on a page that doesn't reference the term.

GOOD: every glossary entry has at least 2 inline link sites in the prose. Terms that appear <2 times don't deserve a glossary entry.

The fix. Pedagogical-review.js dimension 4 catches this. Run before shipping.

8. Hedging language in conceptual explanations

BAD: "We might think of market share as... well, in some sense it's just a set of fractions. Although there are subtleties..."

GOOD: "Market share is a probability distribution over the 5 firms, with the fractions summing to 1. Subtleties are flagged with footnotes."

The fix. Direct, technical, unhedged voice — see SKILL.md Phase 1.4. No automated check; humans spot this during pedagogical review.
