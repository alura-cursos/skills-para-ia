N. Binary search — log(N) by halving the haystack

What you'll learn: binary search finds an element in a sorted array in O(log N) time by repeatedly halving the search range. After this section you'll know how it works, when it breaks, and the off-by-one mistake that catches everyone.

You're looking up a name in a phone book. Do you start at page 1? No — you flip to roughly the middle, see whether the name you want is in the first or second half, and repeat with that half. Each comparison eliminates half the remaining pages. Binary search is exactly this strategy, formalized.

For an array of N sorted elements, you can find any target in roughly log₂(N) comparisons. 1,000,000 elements → 20 comparisons. 1,000,000,000 → 30 comparisons. That's the power of halving: doubling the input adds ONE step.

The catch: the array must be sorted. Sort cost is O(N log N), so binary search is only a win if you'll do MANY lookups against the same dataset. For one-shot lookup, linear scan is fine.

The algorithm. Maintain a search range [lo, hi]. At each step, examine the middle element. If it equals the target, done. If it's too small, discard the lower half (set lo = mid + 1). If too large, discard the upper half (hi = mid − 1). Stop when the range is empty.

binary_search.py python 
def binary_search(arr, target):
    lo, hi = 0, len(arr) - 1          # 1: invariant: target, if present, is in arr[lo..hi]
    while lo <= hi:                   # 2: empty range when lo > hi
        mid = (lo + hi) // 2          # 3: integer midpoint
        if arr[mid] == target:        # 4: found
            return mid                #
        elif arr[mid] < target:       # 5: target is in upper half
            lo = mid + 1              #    discard arr[lo..mid]
        else:                         # 6: target is in lower half
            hi = mid - 1              #    discard arr[mid..hi]
    return -1                         # 7: not found

Line-by-line:

  • Line 1. The invariant: throughout the loop, if the target exists in the array, it sits at some index in [lo, hi]. Both endpoints inclusive.
  • Line 2. Loop condition lo <= hi — when these cross, the range is empty and the target wasn't found. This is where the famous off-by-one lives.
  • Line 3. (lo + hi) // 2 can overflow on huge arrays in fixed-width integer languages (Java, C++). Use lo + (hi - lo) // 2 for safety. In Python it doesn't matter — integers are arbitrary-precision.
  • Lines 5-6. The CRUCIAL detail: when discarding a half, exclude mid itself (mid + 1 or mid − 1). If you write lo = mid, you can infinite-loop when lo + 1 == hi.

In plain words: repeatedly halve the search range, eliminating the side that can't contain the target, until you either find it or the range is empty.

Complexity

  • Time: O(log N) — each iteration halves the range, so log₂(N) iterations suffice.
  • Space: O(1) — only 3 integer variables (lo, hi, mid).
  • Recursion alternative: O(log N) call stack depth. Slightly worse constant factor, often easier to reason about for first-time learners.

Takeaway. Binary search is the prototypical example of halving — reducing problem size by a constant factor per step gives O(log N). You'll see this pattern again in §[N+1] (red-black trees use rotation to maintain logarithmic depth) and §[N+2] (segment trees layer log N halvings recursively).

Edge cases that catch everyone:

  • Empty array. hi = -1 means lo <= hi is false at start; returns -1. ✓
  • Single element. lo = hi = 0; one comparison decides. ✓
  • Duplicates. Binary search returns SOME index of the target, not necessarily the first or last. If you need the leftmost/rightmost occurrence, write a different variant — see §[N+3].
  • Unsorted input. Algorithm silently returns wrong answer. Always assert sorted(arr) in dev builds.
